name: my-plan
description: Instructions for when planning new features. Use when plan mode is enabled.
---

- Keep big picture in mind: Include how the new features fits and relates to existing repo structure
- Use Phases for development
    - 1. includes writing tests and validating their validity with the user
    - 2. includes implementing the features to satisfy the tests and business goal
    - 3. includes reviewing code changes, updating README and allowing user to validate work done
- Include **pseudocode snippets** showing how to connect to existing code
- Clearly document what is **already implemented** vs. what needs to be built
- Specify **new classes/methods** and how they will be organized
- Be careful about **making assumptions**, check in with the user when there is ambiguity about existing state or desired functionality. Seek clarification when things aren't clear.

When asking user question, **suggest a few options** with pros and cons given best practice and existing code.

Be concise and to the point.

**At the end always list unresolved questions, if there are any.**
